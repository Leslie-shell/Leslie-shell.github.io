MySQL 锁机制与事务整理

1. 锁分类

1.1 全局锁（Global Lock）

  • flush tables with read lock

    • 执行后整个数据库处于只读状态
    • 阻塞操作：
      • 数据增删改操作（INSERT、DELETE、UPDATE 等）
      • 表结构变更（ALTER TABLE、DROP TABLE 等）

  • 释放全局锁

  • 自动释放：会话断开时自动释放

  • 备份数据库时：

    • 对事务性存储引擎（InnoDB），可用 mysqldump --single-transaction，利用 MVCC 不阻塞业务
    • 对 MyISAM（非事务性），仍需全局锁

1.2 表级锁（Table Lock）

  • 读锁（共享锁）

    • 当前会话可读取表
    • 阻止其他会话写操作

  • 写锁（独占锁）

    • 当前会话可读写表
    • 阻止其他会话任何操作

  • 释放锁

1.3 元数据锁（MDL，Metadata Lock）

  • 自动加锁，不需要显示声明
  • 作用：
    • 防止在 CRUD 操作时表结构被修改
    • 事务提交后释放
  • 示例场景（长事务阻塞）
    1. 线程 A 开启事务并执行 SELECT -> 加 MDL 读锁
    2. 线程 B 执行 SELECT -> 不阻塞
    3. 线程 C 执行 ALTER TABLE -> 阻塞，等待 MDL 写锁
    4. 后续所有 SELECT/UPDATE 也被阻塞，因为 MDL 写锁优先
  • ⚠ 注意：DDL 操作前需检查长事务，必要时可 kill 长事务

1.4 意向锁（Intention Lock）

  • 目的：快速判断表中是否有记录被加锁
  • 作用：
    • 协助行级锁判断冲突，减少锁冲突检查开销
  • 类型：
    • 意向共享锁（IS）
    • 意向排他锁（IX）

1.5 AUTO_INCREMENT 锁

  • 用于自增主键字段
  • 特性：
    • 锁不是事务提交后释放，而是插入语句执行完释放
    • 大量插入时可能影响性能
  • InnoDB 优化：
    • 5.1.22 后使用轻量级 AUTO-INC 锁

1.6 行级锁（Row Lock）

  • 仅 InnoDB 支持
  • 支持高并发，但锁开销大
  • 只在存储引擎层实现，MySQL 服务器层不了解

2. 事务

2.1 基本操作

  • ACID：
    • 原子性：操作要么全部成功，要么全部失败
    • 一致性：事务前后数据保持一致
    • 隔离性：事务互不干扰
    • 持久性：事务提交后数据持久化

2.2 隔离级别

隔离级别 特点 问题
读未提交 可读到未提交数据 脏读
读已提交 只能读到已提交数据 不可重复读
可重复读 同一事务多次读取结果一致 幻读（InnoDB用MVCC解决）
串行化 强制事务串行执行 性能低，几乎不用

2.3 死锁

  • 两个或多个事务相互占用对方资源，形成恶性循环
  • InnoDB 处理方式：
    • 检测死锁
    • 回滚持有最少行级排他锁的事务

2.4 事务日志

  • 预写式日志（Write-Ahead Logging）
    • 内存中修改数据的副本
    • 记录修改操作到持久化日志（顺序 IO）
    • 数据刷回磁盘时才更新实际表
    • 写两次磁盘（日志 + 数据）提高效率
  • 崩溃恢复：日志持久化后，数据可自动恢复

2.5 MySQL 中事务特性

  • 自动提交

  • 存储引擎混合

    • MySQL 服务器不管理事务，依赖存储引擎
    • 混合事务表可能导致回滚问题

  • 隐式/显式锁

    • InnoDB 使用 两阶段锁定协议（2PL）
      • 事务开始后只能加锁，锁在提交时释放
    • LOCK TABLES / UNLOCK TABLES 是服务器层锁，不建议 InnoDB 使用

3. 多版本并发控制（MVCC）

  • 行级锁变种，避免加锁操作，开销低
  • 通过快照实现：
    • 不同事务同时读取同一张表，可看到不同快照
  • 实现机制（InnoDB）
    • 每个事务分配唯一事务 ID（trx_id）
    • 修改数据写入 Undo 日志，指向回滚指针
    • 读取时比较事务 ID 与 read_view 判断可见性
    • 删除记录在 info flags 设置 deleted 位，同时写入 Undo + redo 日志
  • 适用隔离级别：
    • 仅可重复读（REPEATABLE READ）和读未提交（READ UNCOMMITTED）

5. 总结

  • MySQL 锁机制多层次：
    • 全局锁、表级锁、行级锁、意向锁、MDL、AUTO-INCREMENT 锁
  • InnoDB 支持事务、行级锁、MVCC
  • 事务日志提高写效率，支持崩溃恢复
  • 长事务 + MDL 写锁可能阻塞其他操作
  • 备份策略应结合事务隔离和存储引擎特性
