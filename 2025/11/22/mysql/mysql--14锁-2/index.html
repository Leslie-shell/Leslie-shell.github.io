MySQL 锁机制总结

MySQL 锁机制

1. 锁的分类

MySQL 中锁主要分为 表锁 和 行锁 两类，还有一些辅助锁类型。

1.1 表锁（Table Locks）

  • 特点：

    • 锁定整张表，阻止其他事务对表进行修改。
    • 适用于大量数据批量操作或小表操作。

  • 实现：

    • MyISAM 默认使用表锁。

  • 优缺点：

    • 优点：实现简单，开销小。
    • 缺点：并发性能差，容易阻塞其他操作。

1.2 行锁（Row Locks）

  • 特点：
    • 锁定单条或多条记录，允许高并发读写。
    • 主要由 InnoDB 实现。
  • 类型：
    1. 共享锁（S Lock）
      • 允许事务读数据，但阻止其他事务写。
    2. 排他锁（X Lock）
      • 允许事务读写数据，阻止其他事务读写。
  • 优缺点：
    • 优点：并发性能高。
    • 缺点：实现复杂，可能发生死锁。
  • 使用场景：
    • 事务控制下的 SELECT … FOR UPDATE / LOCK IN SHARE MODE

1.3 自增锁（AUTO-INC Lock）

  • 特点：
    • InnoDB 对自增列插入操作会加特殊的自增锁。
    • 确保插入自增列时不会出现重复值。
  • 作用范围：只影响自增列的插入操作，不影响普通列。

1.4 意向锁（Intention Lock）

  • 特点：
    • 用于标识事务想要对表的哪一行加行锁。
    • 分为 意向共享锁（IS） 和 意向排他锁（IX）。
  • 作用：
    • 协助数据库在表锁和行锁之间快速判断是否可以加锁。
    • 避免全表扫描行锁，优化并发性能。

2. InnoDB 锁的实现机制

InnoDB 采用 多版本并发控制（MVCC）+ 行锁 + 索引锁 来保证事务的隔离性。

2.1 行锁实现

  • 加锁对象：索引记录（不是整行）

  • 锁类型：

    1. Record Lock：记录锁，加在索引的记录上。
    2. Gap Lock：间隙锁，加在索引记录之间的间隙，防止幻读。
    3. Next-Key Lock：记录锁 + 间隙锁组合，InnoDB 默认锁策略。

2.2 MVCC（多版本并发控制）

  • 作用：
    • 支持 读已提交（RC） 与 可重复读（RR） 隔离级别下的非阻塞读。
    • 通过版本链保存旧数据，读操作不会阻塞写操作。
  • 原理：
    • 每行记录存储两个隐藏字段：
      • DB_TRX_ID：最后修改该行的事务 ID。
      • DB_ROLL_PTR：回滚指针，指向旧版本数据。
    • 事务读取时根据版本号判断可见性。

3. 锁粒度与锁策略

锁类型 粒度 阻塞情况 实现表
表锁 全表 读写冲突阻塞 MyISAM / InnoDB
行锁 单行 写写/写读冲突 InnoDB
Gap Lock 索引间隙 幻读防止 InnoDB
Next-Key Lock 索引记录 + 间隙 防幻读 InnoDB
意向锁 表级 表与行锁协作 InnoDB

4. 锁的应用场景

  1. 事务更新数据：

    • 保证事务安全，避免并发修改出现脏数据。

  2. 防止幻读：

    • 使用 Next-Key Lock + RR：

  3. 高并发读取：

    • 依靠 MVCC，普通 SELECT 不加锁。

  4. 自增列插入：

    • 自动加 AUTO-INC Lock。

5. 死锁与锁优化

5.1 死锁原因

  • 多事务交叉加锁。
  • 锁粒度过大（表锁）。
  • 事务执行顺序不一致。

5.2 死锁解决

  • 监控 SHOW ENGINE INNODB STATUS;
  • 调整事务顺序或拆分操作。
  • 使用较短事务。
  • 尽量按主键顺序访问表。

5.3 锁优化策略

  1. 使用索引避免全表扫描。
  2. 避免长事务和大批量更新。
  3. 对只读操作使用 READ COMMITTED。
  4. 对写操作先加索引、后更新，减少锁冲突。

6. 小结

  • MySQL 锁机制核心：行锁 + MVCC。
  • InnoDB 特性：
    • 支持事务 ACID。
    • 避免脏读、不可重复读、幻读。
  • 锁类型选择：
    • 高并发场景 → 行锁 + MVCC。
    • 批量操作 → 表锁。
  • 注意事项：
    • 索引设计直接影响锁效率。
    • 长事务容易导致死锁或阻塞。
    • 理解意向锁和间隙锁，有助于理解 InnoDB 的锁竞争行为。
