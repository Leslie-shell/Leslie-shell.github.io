MySQL 核心知识整理

1. MySQL 逻辑架构

  • 1.1.1 连接管理和安全性
    • 管理客户端连接、权限验证。
    • 支持 SSL 加密连接。
  • 1.1.2 查询优化和执行
    • MySQL 解析 SQL 生成解析树。
    • 优化器重写 SQL、选择访问路径、索引。
    • 查询缓存已废弃（8.0）：全局锁导致高并发性能瓶颈。

2. 并发控制与锁机制

  • 锁类型

    • 读锁（共享锁, Shared Lock）：允许多个事务同时读取，禁止写入。
    • 写锁（排他锁, Exclusive Lock）：阻止其他事务读取或写入。

  • 锁粒度

    1. 表锁

    2. 行锁（Row Lock）

  • InnoDB 行锁类型

    • 记录锁（Record Lock）
    • 间隙锁（Gap Lock）
    • Next-Key Lock（记录锁 + 间隙锁）

3. 事务

  • 开启事务

  • ACID 原则

    • A: 原子性
    • C: 一致性
    • I: 隔离性
    • D: 持久性

  • 隔离级别

    隔离级别 脏读 不可重复读 幻读
    读未提交 ✅ ❌ ❌
    读已提交 ❌ ❌ ❌
    可重复读 ❌ ✅ InnoDB 使用 Next-Key Lock 防幻读
    串行化 ❌ ✅ ✅

  • 死锁

    • 多个事务互相等待对方释放资源导致循环阻塞。
    • InnoDB 处理：
      • 检测死锁
      • 回滚持有最少行锁事务

4. 事务日志（Redo Log & Undo Log）

  • 预写日志（WAL）原理
    • 修改先写内存副本
    • 再追加写入硬盘事务日志
    • 数据异步刷回磁盘数据页
    • 提高事务效率，支持崩溃恢复
  • 写入顺序
    1. 写事务日志
    2. 异步刷新数据页
  • 代码示例

5. 自动提交与显式锁

  • 自动提交
  • 锁定协议
    • InnoDB 使用两阶段锁定协议（2PL）
      1. 加锁阶段
      2. 解锁阶段（事务提交或回滚时释放）

6. 多版本并发控制（MVCC）

  • 原理
    • 通过数据快照保证事务读到一致视图。
    • 避免大部分加锁开销。
  • 实现
    • 事务分配 Transaction ID
    • 修改记录写入 Undo 日志
    • 读取时结合 Undo 日志生成快照
  • 适用隔离级别
    • 可重复读、读未提交
  • 流程示意

7. 复制与高可用

  • 主从复制
    • 保证数据多副本存储
    • 至少三个副本，分布在不同地区
    • 类型：
      • 基于语句（SBR）
      • 基于行（RBR）
  • 生产建议
    • 主从延迟监控
    • 自动故障切换

8. InnoDB 特性与数据字典

  • 数据文件结构
    • MySQL 8.0：表元数据整合到 .ibd 文件
  • JSON 支持
    • 5.7 引入 JSON 类型
    • 8.0 支持 JSON 多值索引
  • 数据字典
    • 8.0 删除基于文件的表元数据，全部放入 InnoDB
  • 原子 DDL
    • 表结构变更具备原子性

9. 锁获取与回滚流程示意

10. 总结

  • MySQL 架构分层：
    • 服务层：连接、解析、优化
    • 存储引擎：数据存储、锁、事务、MVCC、日志
  • 高并发推荐：
    • InnoDB 行级锁 + MVCC
    • 避免混合存储引擎
    • 配置事务日志优化写入性能
  • 复制机制保证高可用和灾难恢复
