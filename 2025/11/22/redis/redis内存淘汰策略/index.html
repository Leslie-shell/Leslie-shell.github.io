Redis 内存管理与淘汰策略

Redis 内存管理是保证缓存高效运行的基础，主要涉及 最大内存配置、内存淘汰策略、内存失效机制。

2. 内存淘汰策略

当 Redis 占用内存达到 maxmemory 时，需要淘汰旧数据，Redis 提供了多种策略：

策略 说明
noeviction 默认策略，写请求超出内存限制时返回错误
allkeys-lru 最近最少使用 (LRU)，从 所有 key 中淘汰
volatile-lru LRU，从 设置过期时间的 key 中淘汰
allkeys-random 从 所有 key 中随机淘汰
volatile-random 从 设置过期时间的 key 中随机淘汰
volatile-ttl 根据 TTL 淘汰，越早过期越先淘汰
allkeys-lfu 最少使用频率 (LFU)，从 所有 key 中淘汰，Redis 4.0+ 支持
volatile-lfu LFU，从 设置过期时间的 key 中淘汰，Redis 4.0+ 支持
  • 注意：
    • 使用 volatile-* 策略时，如果没有设置过期的 key 可以被淘汰，则行为与 noeviction 相同，写请求会报错。

3. 内存失效策略（Key 过期机制）

Redis key 一般会设置过期时间，过期后会清理内存，策略包括：

  1. 定时清除（主动）
    • 为每个设置过期时间的 key 创建定时器
    • 到期立即删除 key
    • 优点：内存友好
    • 缺点：CPU 消耗大，可能影响响应时间
  2. 惰性清除（被动）
    • key 被访问时才检查是否过期
    • 优点：节省 CPU
    • 缺点：过期 key 若不被访问，会长期占用内存
  3. 定期扫描清除（主动）
    • Redis 周期性扫描一定数量的 key 并清理过期 key
    • 是前两者的折中方案，可调节扫描间隔和扫描耗时，平衡 CPU 和内存消耗
  • 实际使用中，Redis 同时采用 惰性清除 + 定期扫描清除，既保证内存清理，又节省 CPU。
