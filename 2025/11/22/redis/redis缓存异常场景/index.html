Redis 缓存异常场景与优化策略

Redis 作为缓存系统，在高并发或异常情况下可能出现一些问题，主要包括 缓存穿透、缓存击穿、缓存雪崩，同时涉及 缓存预热与缓存降级。

1. 缓存穿透

  • 概念：请求的数据在缓存中不存在，也在数据库中不存在，每次请求都会直接查询数据库，造成数据库压力。
  • 解决方案：
    1. 布隆过滤器（推荐）
      • 用于判断数据是否存在，例如：
        • 爬虫系统 URL 去重
        • 垃圾邮件过滤
        • 黑名单校验
    2. 返回空对象
      • 将查询结果为空的数据也缓存，避免重复查询数据库

2. 缓存击穿

  • 概念：某个热点 key 高并发访问，在 key 失效瞬间，所有请求同时穿透缓存访问数据库。
  • 解决方案：
    1. 互斥锁（mutex key）
      • 只有一条线程查询数据库并更新缓存，其他线程等待
    2. 热点数据永不过期
      • 对关键热点数据设置固定或非常长的过期时间

3. 缓存雪崩

  • 概念：大量 key 在同一时间过期，大量请求同时落到数据库，造成数据库压力过大甚至宕机。
  • 解决方案：
    1. 均匀过期
      • 给 key 的有效期增加随机值，避免集中过期
    2. 互斥锁
      • 与缓存击穿解决方法一致
    3. 缓存永不过期 + 异步更新
      • key 永不过期，后台线程异步刷新缓存
    4. 双层缓存策略
      • 主缓存：有效期较短，主读取缓存
      • 备份缓存：有效期长，读取失败时 fallback，主缓存更新时同步更新备份缓存

4. 缓存预热

  • 概念：系统上线前，将热点数据提前加载到 Redis 中，避免初期大量请求落到数据库。
  • 作用：
    • 提升系统上线后的响应速度
    • 减少数据库初期压力

5. 缓存降级

  • 概念：缓存失效或 Redis 服务挂掉时，不访问数据库，直接返回默认数据或服务内存中的缓存。
  • 应用：
    • 热点数据缓存到服务内存
    • 避免数据库遭受巨大压力
  • 注意：
    • 缓存降级通常是有损操作，应尽量减少对业务影响
