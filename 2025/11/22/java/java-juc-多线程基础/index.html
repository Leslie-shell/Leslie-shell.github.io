多线程基础概念

1. 多线程核心概念

  • 同步 (Synchronous) 与 异步 (Asynchronous)
  • 并发 (Concurrency) 与 并行 (Parallelism)
  • 临界区 (Critical Section)
    • 临界区表示共享资源，每次只能有一个线程访问，其他线程必须等待。
  • 阻塞 (Blocking) 与 非阻塞 (Non-Blocking)
  • 死锁 (Deadlock)、饥饿 (Starvation) 与 活锁 (Livelock)
    • 饥饿：某些线程无法获得资源，一直无法执行。
    • 活锁：线程主动释放资源给其他线程，但资源不断在线程间跳动，导致没有线程能完成任务。

2. 并发级别

  • 并发级别受临界区控制策略影响，可分为：
    • 阻塞 (Blocking)
    • 无饥饿 (No Starvation)
    • 无障碍 (Barrier-Free)
    • 无锁 (Lock-Free)
    • 无等待 (Wait-Free)

3. 并行的两条定律

  • Amdahl 定律 (阿姆达尔定律)

    • 定义并行化后的加速比理论上限。
    • 加速比 = 优化前耗时 / 优化后耗时

  • Gustafson 定律

    • 如果可并行化的代码比例足够大，加速比随 CPU 数量线性增长。

4. Java 内存模型 (JMM)

  • 原子性 (Atomicity)
  • 可见性 (Visibility)
  • 有序性 (Ordering)

多线程编程需要注意的问题

1. 线程安全问题

1.1 原子性

  • 并发编程中很多操作不是原子操作：

1.2 可见性

  • 多线程访问共享变量时，一个线程修改，其他线程必须能立即看到变化。

1.3 有序性

  • JVM 与 CPU 可能会对指令重排，需要保证线程间操作顺序正确。

2. 活跃性问题

  • 活跃性：某件正确的事情最终会发生。
  • 常见问题：
    • 死锁：线程环形等待锁，永远阻塞。
    • 活锁：线程不断让出资源，无法完成任务，但线程未阻塞。
    • 饥饿：线程无异常却无法运行。

3. 性能问题

  • 上下文切换 (Context Switch)
    • CPU 在不同线程间切换时，需要保存当前线程状态并加载下一个线程状态。
    • 上下文切换耗时虽短（微秒级），但频繁切换会影响性能。
  • 优化方法：
    • 无锁并发编程
    • CAS 算法
    • 协程 / 虚拟线程

4. 死锁产生条件

  1. 互斥条件：资源一次只能被一个进程使用
  2. 占有且等待：进程请求资源阻塞时，对已获得资源保持不放
  3. 不可强行占有：已获得的资源不能强行剥夺
  4. 循环等待：多个进程形成环形等待

5. 避免死锁

  • 按固定顺序获取锁
  • 尝试加锁时设置超时时间，失败后释放已占锁并重试

6. 公平锁与非公平锁

  • 公平锁 (Fair Lock)
    • 加锁时优先考虑等待队列线程，先来先得
  • 非公平锁 (Nonfair Lock)
    • 直接尝试获取锁，获取失败自动排队
    • 性能比公平锁高 5~10%
    • Java ReentrantLock 默认使用非公平锁

7. 线程安全总结

  • 原子性、可见性、有序性是基本保证
  • 避免死锁、饥饿、活锁
  • 减少上下文切换提高性能
