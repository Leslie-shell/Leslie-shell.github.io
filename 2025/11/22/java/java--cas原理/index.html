CAS 与 Atomic

一、什么是 CAS

  • CAS（Compare-And-Swap）：比较并交换，是一条 CPU 并发原语，用于判断内存中某个值是否为预期值，如果是，则将其更新为新的值，该操作是原子的。
  • 操作流程：
    1. 内存中有一个变量 V，预期值为 A。
    2. 当 V 的实际值等于 A 时，将 V 更新为 B。
    3. 整个操作保证原子性。

二、CAS 基本原理

  • 在 Intel CPU 中，CAS 使用 cmpxchg 指令实现，该指令是 CPU 原语，能够保证操作的原子性。

三、CAS 在 Java 中的应用

  • Java 编程中通常不直接使用 CAS，而是通过 JDK 封装好的并发工具类（位于 java.util.concurrent 包中）间接使用。
  • 典型例子：
    • AtomicInteger 可以解决 i++ 非原子性问题。
    • 实现原理：依赖 volatile 保证可见性，以及 CAS 操作保证原子更新。

四、CAS 的问题与局限

CAS 并非万能，使用时需要注意实际场景。

4.1 ABA 问题

  • 问题：变量值从 A 变为 B，又变回 A，CAS 无法感知中间变化，可能导致逻辑错误。
  • 解决方案：
    • JDK 1.5 提供 AtomicStampedReference，使用 引用 + 标志位，在比较时同时检查引用和标志，保证更新安全。

4.2 自旋开销问题

  • CAS 冲突后会自旋重试，如果竞争激烈，CPU 空转导致性能下降。
  • 解决方案：
    • 限制自旋次数
    • 可适当延迟执行

4.3 只能保证单个变量原子性

  • CAS 只能保证单个共享变量的原子操作。
  • 多个共享变量需要同时修改时，CAS 无法保证整体原子性，例如同时给 i 和 j 加 1。

五、Atomic 操作类

  • Java 提供多种 原子操作类，实现线程安全操作。
  • 变量类型：
    • 局部变量：线程私有，栈上，天然线程安全
    • 共享变量：堆上，多线程共享，需要原子性保证

5.1 Atomic 类分类

  1. 原子操作基本类型：AtomicInteger, AtomicLong
  2. 原子操作数组类型：AtomicIntegerArray, AtomicLongArray
  3. 原子操作引用类型：AtomicReference
  4. 原子操作更新属性：AtomicReferenceFieldUpdater, AtomicIntegerFieldUpdater

六、AtomicLong 与 LongAdder

  • LongAdder（JDK 1.8 引入）在高并发场景下效率高于 AtomicLong。
  • 原理：
    • AtomicLong 单点更新，通过 CAS 竞争同一变量，竞争激烈时性能下降
    • LongAdder 分段累加，每个线程更新不同槽位，减少冲突，最终汇总各槽位结果

七、总结

  • CAS 是底层并发原语，保证单变量的原子操作
  • CAS 问题：
    • ABA 问题
    • 自旋开销
    • 多变量操作原子性问题
  • Java 提供 Atomic 系列工具类封装 CAS，简化开发
  • 高并发场景下推荐使用 LongAdder 替代 AtomicLong 提高性能
