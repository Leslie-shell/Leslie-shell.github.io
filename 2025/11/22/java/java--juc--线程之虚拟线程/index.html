Java 虚拟线程（Virtual Threads

1. 概述

虚拟线程（Virtual Thread）是 Java Project Loom 提供的一种轻量级线程。
它由 JVM 调度，而不是由操作系统调度，因此可以创建海量线程，适合 I/O 密集型任务。

传统线程 = OS 线程
虚拟线程 = JVM 管理的轻量线程（类似 goroutine / coroutine）

2. 虚拟线程解决了什么问题

2.1 阻塞 I/O 导致资源浪费

传统线程在执行 I/O（数据库、网络、文件）时会阻塞 OS 线程，导致：

  • 线程占着内核资源却在等待
  • 大量线程导致上下文切换开销大
  • 系统可承载并发有限（几千级）

虚拟线程遇到阻塞时：

  • 只是挂起虚拟线程自身
  • OS 线程立即解放去执行其他任务

因此系统可以轻松支持 百万级并发。

3. 核心原理（非常重要）

3.1 Virtual Thread 遇到 I/O 阻塞时

  1. 虚拟线程被 park（挂起）
  2. 栈帧保存到 JVM 的堆内存
  3. Carrier Thread（OS 线程）被释放
  4. I/O 完成后，虚拟线程被 unpark（恢复）

所有调度动作发生在 JVM 内，而不是 OS。

3.2 调度特性

  • 切换速度远高于 OS 线程
  • 没有复杂的内核态开销
  • 可以创建大量线程而不导致崩溃

4. 虚拟线程的关键优势

4.1 适合 I/O 密集型任务

  • 网络 I/O
  • 文件 I/O
  • RPC 调用
  • 数据库操作

阻塞不会导致 OS 线程浪费，因此吞吐量更高。

4.2 创建成本极低

传统线程需要：

  • 1MB 栈空间
  • OS 调度
  • 昂贵的上下文切换

虚拟线程：

  • 栈按需增长
  • JVM 调度
  • 切换成本极低

4.3 保持同步代码风格

不像 Reactor、CompletableFuture 那样复杂。
虚拟线程让你写同步代码，却获得异步性能。

5. 基本使用方式

5.1 创建虚拟线程

5.2 虚拟线程池（每任务一个线程）

5.3 与普通线程对比

项目 平台线程（OS 线程） 虚拟线程
创建成本 高 极低
调度方 OS 内核 JVM
阻塞效果 阻塞 OS 线程 不阻塞 OS 线程
适用场景 CPU 密集 I/O 密集
并发能力 几千 上百万

6. 与 CPU 密集型任务

虚拟线程 不能提升 CPU 性能。

CPU 密集型仍然由 OS 限制在 CPU 核心数上，适合使用固定线程池。

7. Pinning（固定）问题（虚拟线程被强制绑死在一个 OS 线程上，不能释放，不能切换。）

会导致 Pin 的场景：

  • synchronized 阻塞
  • JNI 调用阻塞
  • 部分未优化的文件 I/O

JDK 正在持续优化以减少 pinning。

8. 常见使用场景

强力推荐（I/O 密集）

  • Web 请求处理
  • 微服务下游调用
  • 数据库访问
  • Redis 调用
  • HttpClient、大量并发任务
  • Web Crawler
  • 整合阻塞型 API 的系统

不推荐（CPU 密集）

  • 大量计算任务
  • 视频编码、图像处理

9. 一个最简单的例子：100 万并发任务

传统线程：直接崩
虚拟线程：轻松运行

10. 总结

  1. 虚拟线程是 JVM 调度的轻量线程，不是 OS 线程
  2. 阻塞不会浪费 OS 线程，是 I/O 密集型业务的终极方案
  3. 可以轻松承载百万级线程
  4. 保持同步编程模型，简单易读
  5. 不会提高 CPU 密集性能
  6. 未来 Java 并发模型的主流方向
