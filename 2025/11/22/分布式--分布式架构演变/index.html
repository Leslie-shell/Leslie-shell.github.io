大型网站架构演进

  1. 单机架构
  2. 单机负载告警，数据库与应用分离
  3. 应用服务器负载告警 → 集群化
    • 引入负载均衡设备
    • 分布式 Session
      • Session Sticky：会话粘滞
      • Session Replication：会话复制
      • Session 集中存储
      • Cookie Based
  4. 数据库读压力增大 → 读写分离
    • 数据库主从复制
    • 搜索引擎
    • 分布式缓存
  5. 弥补关系数据库不足 → 引入分布式存储系统
  6. 数据库遇瓶颈 → 分库分表
    • 垂直拆分（分库）：按业务拆分，需解决表关联和分布式事务问题
    • 水平拆分（分表）
  7. 应用拆分与服务化
    • 应用拆分
    • 服务化
  8. 消息中间件（异步 + 解耦）
  9. CDN（内容分发网络）
    • 将内容分发到离用户最近的节点，加速访问
    • 网络缓存技术，节省带宽，提高访问速度
    • 放置静态资源（图片、JS、CSS 等）
    • 浏览器访问流程：DNS → 负载均衡 → 应用服务器 → 缓存/CDN → 渲染

大型网站核心架构要素

  1. 性能指标
    • PV、QPS、TPS、吞吐量、响应时间
  2. 吞吐量指标
    • TPS：每秒事务数
    • QPS：每秒查询数
    • HPS：每秒 HTTP 请求数
  3. Web 性能优化
    • 前端优化
      1. 浏览器缓存
      2. HTTP 请求合并
      3. CSS、JS、图片资源压缩合并
      4. CDN
      5. 页面静态化
      6. 减少 Cookie 传输
    • 服务端优化
      1. 接入层：反向代理、负载均衡
      2. 应用服务器集群
      3. 分布式缓存
      4. 数据库优化：索引、主从复制、读写分离、分库分表
      5. 分布式消息队列，异步操作
    • 单机并发优化
      • CPU 消耗：减少阻塞、同步转异步、队列、降低锁竞争
      • 文件 IO：异步读写、批量操作、限流、缓存、RAID
      • 内存消耗：减少不必要引用、对象池、缓存失效算法
      • 网络 IO：减少交互次数、减少传输量、异步非阻塞
  4. 抢购/超卖问题解决策略
    • 前端：页面静态化、CDN、禁止重复提交
    • 接入层：限制同 IP 访问频率、页面缓存
    • 服务层：Token 防刷、随机返回失败、数据库悲观锁
    • 数据层：主从复制、读写分离、分库分表
  5. 负载均衡
    • 算法：轮询、加权轮询、随机、最少连接、源地址散列
    • SSL 影响：需考虑负载均衡整合
  6. 安全性
    • XSS、SQL 注入、CSRF 等
    • 分类算法：贝叶斯
    • 黑名单：哈希表实现，但内存消耗大

链路追踪（Distributed Tracing）

  1. 定义

    • 将一次分布式请求还原成调用链路
    • 展示各服务节点耗时、请求状态及到达的具体机器

  2. 主要功能

    • 故障快速定位：结合调用链和日志快速定位错误
    • 链路性能可视化：展示阶段耗时和服务依赖关系
    • 链路分析：分析用户行为路径和业务统计

  3. 常用系统

    • 国际：Zipkin、Jaeger、Pinpoint、SkyWalking
    • 国内：阿里鹰眼、美团 Mtrace、滴滴 Trace、新浪 Watchman、京东 Hydra

  4. 开源组件链接

    • Zipkin
    • Jaeger
    • Pinpoint
    • SkyWalking

  5. Zipkin 核心组件

    • Collector：采集链路数据，验证、存储、索引

    • Storage：保存链路信息，支持 Cassandra、Elasticsearch、MySQL

    • Query Service：提供 JSON API 查询链路数据

    • Web UI：可视化展示调用链信息，辅助运维

分布式链路追踪（Zipkin）

  • 概述
    • 在服务运行过程中会产生大量链路信息，产生数据的地方称为 Reporter。
    • Reporter 将链路信息通过 HTTP、RPC、Kafka 等方式发送到 Zipkin 的采集器（Collector）。
    • Zipkin 处理后将链路信息保存到存储器（Storage）中，运维人员可通过 Web UI 查询调用链信息。
  • Zipkin 核心组件
    1. Collector
      • 采集线程获取链路追踪数据后，Zipkin 对其进行验证、存储和索引，并调用存储接口保存数据，以便查询。
    2. Storage
      • 最初为 Cassandra 构建，支持可伸缩存储和灵活模式。
      • 也支持 ElasticSearch、MySQL，后续可扩展第三方存储。
    3. Query Service
      • 存储和索引后的数据可以通过 Query Service 查询，提供 JSON API，方便运维快速定位问题。
    4. Web UI
      • 提供查询、搜索界面，运维人员可直观查看调用链信息，快速识别线上问题。
  • 总结
    • 分布式链路追踪就是将每一次分布式请求还原成调用链路。
    • 核心概念：Trace、Span、Annotation、带内和带外数据、采样、存储。
    • 开源组件多基于 Google Dapper 论文演变而来。
    • Zipkin 核心组件：Collector、Storage、Query Service、Web UI。

华为分布式软总线

  • 传统总线概念
    • 总线是计算机内部各部件传递信息的公用通道，外部设备通过接口电路连接总线。
    • 按信息种类，分为：
      • 数据总线：传输数据
      • 地址总线：传输数据地址
      • 控制总线：传输控制信号

  • 分布式软总线定义
    • 基于华为通信技术积累，参考计算机硬件总线，在 1+8+N 设备间搭建“无形”的总线。
      • 1：手机
      • 8：车机、音箱、耳机、手表/手环、平板、大屏、PC、AR/VR
      • N：其他 IoT 设备
    • 特点：自发现、自组网、高带宽、低时延
  • 功能与原理
    • 架构
      • 协议货架 + 软硬协同层屏蔽不同设备协议差异
      • 总线中枢解析命令，实现设备发现和连接
      • 通过任务总线和数据总线实现文件传输和消息传输
    • 总体目标：设备间无感发现、零等待传输
    • 关键问题：
      1. 设备如何发现和连接？
      2. 多设备互联如何组网？
      3. 多设备多协议如何实现传输？
    • 关键技术：
      • 自发现连接（从手动到自动）
      • 异构网络组网
      • 高效传输机制
