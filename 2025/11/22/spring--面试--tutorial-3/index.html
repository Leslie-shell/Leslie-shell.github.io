Spring 循环依赖解决机制

非常好，这是一个关于Spring框架核心机制的经典面试题。Spring通过**三级缓存（three-level cache）**机制，巧妙解决单例（Singleton）作用域下的Setter/字段注入的循环依赖问题。

1. 什么是循环依赖？

循环依赖是指两个或多个Bean相互依赖，形成闭环：

  • 简单循环：
    • Bean A → 依赖 → Bean B
    • Bean B → 依赖 → Bean A
  • 更长循环：
    • Bean A → Bean B → Bean C → Bean A

2. 前提条件

Spring并非能解决所有类型的循环依赖，前提条件如下：

  1. 单例Bean：只针对Singleton设计。原型（Prototype）Bean循环依赖会抛出 BeanCurrentlyInCreationException。
  2. Setter注入或字段注入（@Autowired）：允许先实例化对象，再注入依赖。
  3. 构造器注入不可行：构造器循环依赖会导致死锁，无法解决。

结论：Spring仅能解决单例、Setter/字段注入方式的循环依赖。

3. 核心机制：三级缓存

Spring容器内部维护三个缓存：

4. 循环依赖解决流程（以A和B相互依赖为例）

  1. 创建A
    • getBean(A) → 一级缓存找不到
    • 实例化A (aInstance)，属性b为空
    • 将A的ObjectFactory放入三级缓存 singletonFactories
  2. 填充A属性
    • 执行 getBean(B)
  3. 创建B
    • getBean(B) → 一级缓存找不到
    • 实例化B (bInstance)，属性a为空
    • 将B的ObjectFactory放入三级缓存
  4. 填充B属性
    • 执行 getBean(A)
    • 关键点：
      • 一级缓存无A
      • 二级缓存无A
      • 三级缓存有A的ObjectFactory
      • 调用 ObjectFactory.getObject() 返回A早期引用，放入二级缓存 earlySingletonObjects，返回给B
  5. 完成B创建
    • B注入A的早期引用
    • B初始化完成，放入一级缓存，清理二三级缓存
  6. 完成A创建
    • A注入完整B
    • A初始化完成，放入一级缓存，清理二三级缓存

循环依赖解决完成。

5. 为什么需要三级缓存？

  • AOP代理的兼容性：
    • 如果Bean需要代理，早期暴露的对象可能需要返回代理对象。
    • ObjectFactory延迟生成代理，保证单例一致性。
  • 二级缓存不足：二级缓存过早确定对象类型，无法延迟处理代理逻辑。
  • 三级缓存作用：在循环依赖且Bean被AOP代理时，延迟代理生成时机，保证一致性和单例性。

6. 总结

特性 说明
解决范围 单例Bean，Setter/字段注入的循环依赖
无法解决 构造器注入的循环依赖、原型Bean循环依赖
核心机制 三级缓存：singletonObjects（一级），earlySingletonObjects（二级），singletonFactories（三级）
关键步骤 提前曝光：在Bean实例化后、属性填充前，将ObjectFactory放入三级缓存，供其他Bean引用
设计精髓 将实例化和依赖注入分离，打破循环依赖“死锁”
缓存意义 三级缓存主要为兼容AOP代理，保证代理生成时机一致性和单例性

注意：虽然Spring机制强大，但循环依赖通常反映高耦合设计，应尽量避免。
