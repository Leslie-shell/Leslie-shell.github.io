一、jstack

jstack 用于打印 Java 进程中 所有线程的执行栈和状态，是线上排查 CPU 飙高、卡死、死锁问题的核心工具。

典型用途：

  • CPU 使用率异常
  • 接口无响应 / 系统假死
  • 线程池耗尽
  • synchronized / Lock 死锁

四、jstack 线程头字段逐项解析

4.1 线程名：TimerQueue

  • JVM 内部线程
  • 与 java.util.Timer、定时调度机制有关
  • 非业务线程

4.2 线程编号：#44

  • JVM 内部顺序编号
  • 仅用于区分线程

4.3 daemon

  • 守护线程
  • JVM 退出时不会等待该线程结束

4.4 Java 优先级：prio=5

  • Java 线程优先级范围：1~10
  • 5 为默认值

4.5 OS 优先级：os_prio=31

  • 操作系统线程优先级
  • 在 macOS / BSD 系统中数值偏大
  • 通常无需关注

4.6 CPU 使用时间：cpu=0.12ms

  • 线程自创建以来累计消耗 CPU 时间
  • 数值极低

结论：

该线程没有忙等或死循环

4.7 存活时间：elapsed=2072280.54s

  • 单位：秒（约 24 天）
  • 表示 JVM 长期运行

4.8 JVM 内部线程 ID：tid=0x00007fbf5b8fa800

  • JVM 内部管理线程使用
  • 排障中一般不使用

4.9 本地线程 ID：nid=0x1c003（重点）

  • Native Thread ID（操作系统线程 ID）

  • 十六进制

作用：

  • 用于和 top / ps 中的线程 ID 对应

4.10 线程状态：waiting on condition

表示线程：

  • 正在等待条件满足
  • 常见于 wait / park / sleep

特点：

  • 不占 CPU
  • 不持有锁

4.11 栈内存地址

  • JVM 为线程分配的栈地址
  • 可忽略

五、如何快速判断“问题线程”？

判断维度 是否异常
状态为 RUNNABLE 可能
CPU 时间高 可能
BLOCKED 锁问题
WAITING + CPU 低 正常
daemon + 系统线程 正常

七、线上排查案例 1：CPU 飙高

现象：

  • CPU 100%
  • 机器未宕机

排查过程：

  1. top -Hp pid 定位高 CPU 线程
  2. TID → 16 进制
  3. jstack 定位到具体代码行

结果：

  • while(true) 未加 sleep
  • 无限重试逻辑

八、线上排查案例 2：接口无响应 / 假死

现象：

  • 请求堆积
  • CPU 不高

jstack 特征：

  • 大量线程状态为 BLOCKED
  • 卡在 synchronized

原因：

  • 锁粒度过大
  • 单点锁竞争

九、线上排查案例 3：线程池耗尽

现象：

  • 新请求直接失败

jstack 特征：

  • 大量 pool-x-thread-y
  • 状态一致，卡在同一行 I/O 或 RPC

结论：

  • 下游服务阻塞
  • 线程池配置不合理
