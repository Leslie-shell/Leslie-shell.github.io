Spring Boot 默认配置坑点总结

1. 默认连接池 HikariCP 的坑

❌ 坑 1：maximumPoolSize 太小（CPU*2+1）

Spring Boot 默认：

如果你的服务器是 4 核：

对中高并发项目完全不够，表现为：

  • 应用偶尔卡顿
  • SQL 等待时间长
  • 报错：Connection is not available

✔ 正确做法：根据业务峰值调大

❌ 坑 2：maxLifetime < MySQL wait_timeout 导致连接被杀

MySQL 默认 wait_timeout=28800 秒（8 小时）

HikariCP 默认 maxLifetime=30 分钟

导致：

  • MySQL 关闭闲置连接
  • HikariCP 还在使用 → 报错 “connection reset”

✔ 正确做法：让 maxLifetime 稍小于数据库 timeout

4. 默认线程池问题（@Async / WebClient）

Spring Boot 默认使用：

  • SimpleAsyncTaskExecutor（无限创建线程 → OOM 风险）
  • WebFlux 默认：Schedulers.parallel(本地 CPU 核心数)

❌ 坑：默认线程池无限创建线程导致 CPU100%

出现场景：

  • 大量 @Async
  • WebClient 高并发
  • 定时任务异常重跑

✔ 正确做法：自定义线程池

5. 默认静态资源路径太多 → 资源被错误暴露

Spring Boot 默认扫描路径：

如果误把敏感文件放入其中，会被暴露。

✔ 强制关闭某些目录

6. 默认日志（logback）坑点

❌ 坑：日志不能自动滚动（默认 console）

部署到服务器时：

  • 日志全在控制台
  • logrotate 没配置 → 日志可能吃满磁盘

✔ 正确做法：logback-spring.xml

提供生产滚动策略（按天、按大小）。

9. DevTools 热部署踩坑

DevTools 会：

  • 自动重启（比你以为的更频繁）
