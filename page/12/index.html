Redis 高可用架构

Redis 高可用架构的目标是保证系统在单点故障下仍然可用，同时尽量保证数据一致性和快速恢复。

1. 主从复制（Replication）

  • 概念：将主节点（Master）数据复制到从节点（Slave），保证数据冗余，提高读性能。
  • 特点：
    • 数据复制是单向的：Master → Slave
    • Slave 可用于读操作，提高读取吞吐量
  • 实现原理：
    1. 连接建立阶段：
      • 从节点执行 SLAVEOF <master-ip> <master-port> 命令
      • 保存主节点信息（masterhost、masterport）
      • 建立 TCP 连接，发送 PING 检查连接
      • 进行身份验证（若设置 masterauth）
    2. 数据同步阶段：
      • Slave 会全量同步主节点数据
      • 之后进入增量同步，实时接收主节点写操作
    3. 命令传播阶段：
      • Master 执行写命令 → 异步发送给 Slave
      • Slave 执行命令保持数据一致性
      • 注意：命令传播异步，可能存在短暂延迟

2. 哨兵模式（Sentinel）

  • 概念：Sentinel 负责监控 Redis 集群节点健康状态，实现故障发现、故障转移，并通知客户端。
  • 主要功能：
    1. 监控：监控 Master 和 Slave 节点状态
    2. 故障转移：Master 宕机时，自动选举新的 Master
    3. 通知客户端：通过发布/订阅通知客户端新 Master
  • 实现机制：
    1. Sentinel 与 Redis 节点心跳
      • Sentinel 定期向 Master/Slave 节点发送 INFO 命令获取状态
    2. Sentinel 之间心跳
      • Sentinel 使用 Redis 的订阅/发布功能（频道 sentinel:hello）
      • 共享节点状态和对 Master 的判断
  • 注意事项：
    • 多个 Sentinel 组成集群，保证故障判断准确
    • 哨兵模式可实现自动切换 Master，保证高可用

Redis 缓存异常场景与优化策略

Redis 作为缓存系统，在高并发或异常情况下可能出现一些问题，主要包括 缓存穿透、缓存击穿、缓存雪崩，同时涉及 缓存预热与缓存降级。

1. 缓存穿透

  • 概念：请求的数据在缓存中不存在，也在数据库中不存在，每次请求都会直接查询数据库，造成数据库压力。
  • 解决方案：
    1. 布隆过滤器（推荐）
      • 用于判断数据是否存在，例如：
        • 爬虫系统 URL 去重
        • 垃圾邮件过滤
        • 黑名单校验
    2. 返回空对象
      • 将查询结果为空的数据也缓存，避免重复查询数据库

2. 缓存击穿

  • 概念：某个热点 key 高并发访问，在 key 失效瞬间，所有请求同时穿透缓存访问数据库。
  • 解决方案：
    1. 互斥锁（mutex key）
      • 只有一条线程查询数据库并更新缓存，其他线程等待
    2. 热点数据永不过期
      • 对关键热点数据设置固定或非常长的过期时间

  • 关键指标 mem_fragmentation_ratio：

CAS 与 Atomic

一、什么是 CAS

  • CAS（Compare-And-Swap）：比较并交换，是一条 CPU 并发原语，用于判断内存中某个值是否为预期值，如果是，则将其更新为新的值，该操作是原子的。
  • 操作流程：
    1. 内存中有一个变量 V，预期值为 A。
    2. 当 V 的实际值等于 A 时，将 V 更新为 B。
    3. 整个操作保证原子性。

二、CAS 基本原理

  • 在 Intel CPU 中，CAS 使用 cmpxchg 指令实现，该指令是 CPU 原语，能够保证操作的原子性。
